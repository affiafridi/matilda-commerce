Matilda Commerce: design brief

Status: approved by the owner on 2026-11-25 with the final direction below. Platform name: Matilda Commerce. The official logo is used where it fits, but brand colours are not carried into the interface; each storefront keeps its own identity. Collapsible sidebar, content that uses the full width, Inter, 4 to 6px radii, and a variable-based token layer that is ready for dark mode and right-to-left (logical CSS properties) while shipping light and English only in Phase 2. The logo file has not been supplied yet, so a text wordmark is used.

Phase 2, step 2.9. This is a proposal for your review. No admin UI will be built until you approve it. It covers the visual language, the navigation model, and wireframes of the screens the plan lists. Nothing here is branded: the admin uses a neutral token set that is separate from the three storefront identities.

What I need from you: approve, or mark up, the items in section 8 (decisions). The most consequential ones are the primary-action colour, the typeface, and the information density.

1. Principles

Principle What it means here
Enterprise tool, not a showcase Tables, forms, tabs, drawers. No card grids, no hero areas, no decorative illustration. Shopify Admin is a usability reference only; nothing is copied.
Quiet and flat No gradients, glass, glow or heavy shadows. Separation comes from 1px lines and two background levels. Corner radius 4px on controls and 6px on panels and dialogs. No pill shapes (status labels are square-cornered text on a tinted background).
Dense but readable Default row height 36px, 14px text, 8px spacing grid. A compact option (30px rows) is available per table for power users.
Scope is always visible The brand / market / branch you are working in is on screen at all times, and everything on the page is filtered to it.
The API is the authority Menus show only what you may use, but that is a convenience. Every action is checked again by the server, and the UI shows a clear message if the server refuses.
Accessible by default WCAG 2.2 AA, full keyboard use, visible focus, no information by colour alone, reduced-motion respected. English only in Phase 2 (decision D2-17).

2. Visual tokens

Neutral, neutral grey surfaces so the tool recedes. Colour is reserved for state (success, warning, danger) and one focus colour. The primary action is near-black, so the admin carries no brand colour at all.

state green / amber / red on tinted backgrounds, all ≥ 4.5:1 Status text always carries a word, never colour alone
Type Inter (self-hosted via the framework font loader), system fallback. 12 / 14 / 16 / 20 / 26 px; weights 400, 500, 600. Tabular figures in tables. No decorative faces
Spacing / radius / motion 8px grid (4px half-step). Radius 4px for controls, 6px for panels. Motion limited to 120ms opacity and position changes, removed when reduced-motion is on.
Icons One outline icon set (Lucide), 16px, always paired with a text label in navigation. No emoji.

3. Navigation model

A fixed left navigation grouped as in the admin specification, and a top bar that holds the scope switchers and the account menu. Only groups and items the signed-in person may use are shown, and modules that do not exist yet are hidden rather than shown as placeholders. In Phase 2 the visible items are:

Group Items (permission that reveals it)
Operations Brands and domains (brands.view), Markets (markets.view), Branches (branches.view)
Commerce Customers, read-only (customers.view)
Administration Employees (users.view), Roles and permissions (roles.view), Audit log (audit.view)
Account menu Security (password, two-factor, sign out of all devices), Sign out

The Overview, Finance, Marketing and the rest of Commerce appear only when their modules are built in later phases. A Branch Manager therefore never sees Finance, and a Catalog Manager never sees Employees.

Scope switchers (top bar)

Brand → Market → Branch, each filtered by the one before it and by what the person is assigned. People with platform-wide access also get an "All brands" choice. Someone assigned to one branch sees the switchers disabled and showing that branch. Changing scope clears cached data and returns to the current page in the new scope. The choice is remembered per person on that device and is sent to the API only as a hint that the server validates (a forged value is rejected).

5. How it behaves with the API (technical, for your information)

Topic Decision
Same-origin proxy (D2-02) The admin app forwards /api/* to the API, so the browser only ever talks to the admin's own origin. Session cookies stay host-only and CSRF stays simple. The admin adds the shared secret the API requires; the browser never sees it.
Session and CSRF The session cookie is HttpOnly and never readable by scripts. The per-session CSRF token returned at sign-in is kept in memory only and sent on every change. A 401 sends the person to sign in and back to where they were. A step-up response opens the code dialog and retries the action once.
Data fetching TanStack Query for server data and TanStack Table for tables; React Hook Form with the shared Zod schemas for forms; React context for the scope switchers (decision D2-09). No global state library.
Components shadcn/ui primitives, restyled to these tokens (no default look ships).
Quality gates Keyboard-only walkthrough of every screen, automated accessibility checks (axe, Lighthouse) with a score of 100 required on the shell and sign-in pages, and Playwright end-to-end tests arrive in step 2.10.

6. Screen inventory for step 2.9 and 2.10

2.9 (after approval): sign in, two-factor verify and enroll, recovery code, accept invitation, forgot and reset password, account security, the shell (navigation, switchers, account menu), and the error/empty/loading components. 2.10: brands and domains, markets, branches, employees and assignments, roles and permissions matrix, audit log, customers (read-only). Arabic or right-to-left admin (D2-17), dark mode, mobile-first operational views for production and riders (later phases), real-time alerts, and any brand theming of the admin.
